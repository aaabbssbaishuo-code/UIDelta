# 模式切换、返回走查与清空编号修复

日期：2026-09-08。范围：浏览 → 标注 / UI / 框选、记录页返回、清空本次清单。

## 交互评审

本次使用 emil-design-eng 的焦点保护与交互细节原则，不增加额外动画。

| Before | After | Why |
| --- | --- | --- |
| 模式工具栏点击穿透到网页的 document 捕获监听器，日期输入也可能失焦 | 在 window 捕获阶段隔离工具栏事件，仅在扩展 Shadow DOM 内转发；鼠标操作不抢网页焦点 | 切换工具模式不是点击网页浮窗外部 |
| 保留日期输入焦点后 R 被视为网页输入；记录表单聚焦可能关闭网页浮窗 | 有检查目标时 R 可记录；仅阻止走查期间网页焦点转入插件触发的 blur/focusout 监听器 | 保留取证目标，同时允许输入问题；浏览模式仍保持网页原有行为 |
| 记录页“稍后补充”保留误选草稿 | “返回走查”立即返回、释放目标；误选草稿等待在途写入完成后清理，已保存问题保持原样 | 返回动作不再强迫保存误选，也不回到旧清单页 |
| 清空只删除问题，计数器继续递增 | 显式清空且同事务内确认本次清单为空后将下次编号设为 1 | 普通删除不重排；未删除的新问题、其他会话不受影响 |

## 验证边界与更新步骤

浏览器测试使用独立临时配置、虚构网页和模拟扩展消息，不读取真实走查数据。它验证真实浏览器事件传播、焦点和界面操作，但不代表 Womate 的全部框架、系统原生日期控件或截图 API 均已实机验收。CSS 纯 hover/focus 控制的浮层、先于扩展注册的 window 捕获监听器仍需针对真实页面复测。

重新加载 Chrome 中的 UIDelta 扩展，再刷新需要走查的网页，让新的 content script 生效。验证真实页面：浏览模式打开日期框或导入弹窗 → 点击标注/UI → 选择浮窗内容 → R → 输入描述；误选时点“返回走查”；清空本次清单后再记录，检查编号从 1 开始。

本次不自动清空用户已有记录，不操作真实网页的提交、上传或删除。
