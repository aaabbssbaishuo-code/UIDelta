# UIDelta 产品定义

## 一句话

UIDelta 是开源网页走查工具。在真实网页上测量、记录、取证，把修改依据一起交给前端和 Agent。

**品牌主张：看见问题。说清怎么改。**

把一句「这里不对」，变成一份开发看得懂的走查报告。

English: **See the issue. Make the fix clear.**

## 为谁，解决什么

为负责页面验收、设计还原检查的 UI / 产品设计师而做。前端、产品和测试同学也可以用它记录与沟通页面问题。

发现偏差后，下一步往往是重复截图、找位置、记尺寸、解释目标。UIDelta 把这些依据放回同一条记录，让接手的人知道哪里有问题、要改成什么。

## 三个环节

| 环节 | 用户得到的结果 | 已有能力 |
| --- | --- | --- |
| 测量 | 差多少，直接量。 | 查看尺寸、间距、盒模型、字体与颜色；本地试改与撤销 |
| 记录 | 问题在哪，证据就在哪。 | 元素或区域记录、截图、定位、描述、分类、优先级、检索与筛选 |
| 交付 | 记录一次，接着改。 | HTML 问题单、XLSX 排期表、ZIP 证据包 |

设计对比支持手动导入 Figma Frame JSON 快照，比较期望值与实际值。它是辅助能力，首屏不堆叠技术术语。

## 交付与边界

HTML 用于查看、跟进；XLSX 用于整理与排期；ZIP 提供报告、结构化记录与图片。

Agent 需要项目源码、运行环境与修改授权，依照页面线索验证对应实现后再修改。ZIP 中的元素锚点不等于源码文件与行号。UIDelta 不自带自动修复程序；页面试改不会修改源码。

当前是 v0.9.4 开发者预览版，通过 Chrome 手动加载。无需账号或 API Key，走查数据保存在本地。AI 自动走查、在线 Figma 同步与第三方平台直连仍在规划中。

## 表达与视觉

官网、GitHub、宣传图、商店介绍和发布文案共用 [文案基准](marketing/COPY-GUIDE.zh-CN.md)。先说结果，再给证据，最后给开始使用的方法。

宣传视觉使用白色、石墨色与标注橙。界面正视呈现，同一张图只讲清一个主题。用真实产品界面与明确标注说明功能；不使用倾斜叠卡、装饰性终端或无依据的数据。

截图使用虚构网页与示例数据，来源记录在 `brand/screenshots/SOURCE.json`。重新设计宣传排版不会修改插件源码。

## 面向前端的重点

**让 Codex，接着改。** ZIP 带走页面、元素定位、实测值、截图与修改要求，让前端把已有材料交给项目里的编码 Agent，减少重复查找和上下文整理。

这一主张覆盖页面定位、元素辨认、现场还原、目标澄清、AI 输入组织与按编号复核六类工作。它是有源码依据的流程分析，尚无实际提效比例。完整依据见 [开发者交付调研](marketing/DEVELOPER-HANDOFF-RESEARCH.zh-CN.md)。
