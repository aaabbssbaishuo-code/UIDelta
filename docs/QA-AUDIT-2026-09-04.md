# UIDelta 开发与 UI 自查 · 2026-09-04

## 结论与范围

本轮完成插件源码评审、历史截图 UI 走查、17 项新增回归用例与已确认问题修复。合入了加载版已有的导航、草稿及保存流程修复。源码与本机加载目录的 15 个运行文件统一；没有变更版本、权限或发布线上版本。

自动检查通过，但**不能视为已完成浏览器视觉验收**：尝试操作“项目管理平台”时，工具报告该标签页属于另一个任务。未强行接管，也未操作用户的真实问题记录。下文将自动验证和待实机验收分开。

- 主要范围：检查元素、UI 试改、记录问题、问题清单、交付、插件开关。
- 设计依据：用户历次截图和既定橙色／灰绿风格，使用 `saas-product-ui-system` 的分组、状态与可访问性规则。
- 表面类型：辅助编辑器／走查工具，紧凑密度；页面本身保持主工作区。
- 保留：250px 面板约束、28px 常规按钮、现有图标体系、底部模式栏、R 飞入与计数反馈。
- 层级：上下文 → 主操作内容 → 次要属性／详情；长数据允许展开，不删除原始信息。
- 不修改：被测网站源码、正式问题数据、扩展权限。官网与宣传材料存在另一任务的并行改动，未覆盖。

| 编号 | 级别 | 问题与复现条件 | 处理与验证 |

| A02 | P1 | 参考图异步读取／上传后直接访问 `this.composer`，可能写进后来打开的问题 | 固定原 composer 身份，每次异步返回后验证；上传期间阻止切换记录 |
| A03 | P1 | 保存不等待参考图；截图初始草稿事务可能清理刚上传但尚未挂接的资产 | 参考图在取证草稿事务后上传；保存等待参考图，失败停留表单 |
| A04 | P2 | 移除参考图立即请求删除资产，不符合取消编辑语义 | 只改未提交引用；保存时由既有 `putIssue` 事务清理；后端原本已保护已提交资产 |

| A07 | P2 | 卡片与底部 ZIP 按钮各自锁定，能同时重复生成 | 按格式共享导出锁，同格式所有入口同步状态；失败可重试 |
| A08 | P2 | 勾选交付范围重建整张清单，焦点与滚动连续性受影响 | 原地同步复选框状态，保留 DOM 节点 |
| A09 | P2 | 空态更新选择了第一个 span，把提示写进图标 | 专用 `.empty-hint`，图标单独保留并对辅助技术隐藏 |
| A10 | P2 | 清单截图接口或解码失败后仍显示“加载截图…” | 明确失败状态和“重新加载”按钮，丢弃离开视图后的迟到响应 |
| A11 | P2 | 字体回退栈在窄面板连续换行，挤掉其他属性 | 默认显示首项与剩余数量，键盘可展开完整 CSS 字体列表；不声称首项一定是实际渲染字体 |
| A12 | P2 | 描述字段的可见标题没有绑定输入 | 添加可访问名称及错误说明关联 |
| A13 | P2 | 页面来源被做成按钮，但没有动作，产生“点不动”的假入口 | 改为静态来源信息；保留完整 title 和路径 |
| A14 | P1 | 仓库旧保存逻辑使用等待截图前的描述；返回草稿会遗漏未提交文本 | 合入加载版已验证的最新文本读取、草稿持久化和提交锁定；补入导航及保存回归 |
